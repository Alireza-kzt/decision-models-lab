# داده، نشت و منشأ

## اصل
دادهٔ بیشتر همیشه شواهد بهتر نیست. تکرار، بازنویسی و ترجمهٔ یک سؤال واحد ممکن است در ظاهر نمونه‌های فراوان ایجاد کند اما استقلال آماری نداشته باشد.

## ثبت هر مجموعه
نشانی و revision منبع، مالک و مجوز، تاریخ دریافت، hash، فرمت، schema، label policy، split، group definition، تولیدکنندهٔ برچسب و محدودیت انتقال/ذخیره‌سازی ثبت شود. registry فعلی فقط toy اصلی این آزمایشگاه را ثبت می‌کند؛ هیچ dataset خارجی واقعاً وارد نشده است.

## جلوگیری از نشت
اسناد، paraphraseها، نسخه‌های زبانی، گزینه‌های جابه‌جا‌شده و نمونه‌های از یک rule template را یک گروه بدانید. دادهٔ calibration و test را برای prompt engineering مصرف نکنید. اگر خروجی test دیده و روش تغییر کرد، آن test از این پس development است؛ holdout تازه لازم است.

## دادهٔ مصنوعی
نام generator، نسخه، prompt hash، seed، سیاست دسترسی، اعتبارسنجی و نسبت موارد بازبینی‌شده توسط انسان ثبت شود. synthetic بودن مترادف پاک بودن نیست؛ teacher می‌تواند benchmark را در آموزش دیده باشد. از تولید چند paraphrase و تقسیم آن‌ها بین train/test اجتناب شود.

## دادهٔ خصوصی و API
اجازهٔ ارسال داده به هر ارائه‌دهنده مستقلاً بررسی شود. اطلاعات حساب، مشتری، پژوهش منتشرنشده و نقشهٔ محرمانه در درخواست آزمایشی قرار نگیرد. API key فقط در environment محلی؛ نه در fixture، notebook، commit یا log.

## سیاست storage
Git: schema، metadata، کد، نمونهٔ کوچک مجاز و hash. خارج از Git: checkpoint، dataset حجیم، raw response حساس، cache، secrets. `.gitignore` کمک است، نه ابزار تضمین محرمانگی. پیش از هر push فهرست فایل‌های tracked را بازبینی کنید.
